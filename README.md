# APOLLO NEXT — бронювання

Внутрішній сервіс бронювання зустрічей APOLLO NEXT: заміна Calendly, що
працює цілком на Cloudflare Workers і не має обмежень за місцями.

Форк [CCCrafts/punctual](https://github.com/CCCrafts/punctual) (MIT) —
рушій той самий, зверху додано брендинг APOLLO, український інтерфейс і
вирізано публічний маркетинговий сайт. Апстрім підключений як `upstream`.

> Інтерфейс, листи та `.ics` — українською. Код, коментарі, REST API та
> MCP лишаються англійськими: перше читають гості, друге — розробники.

## Швидкий старт (локально)

```bash
npm install
npm run migrate:local
npm run dev          # http://localhost:8787
```

Шрифти Halvar і `wrangler.production.toml` у git не зберігаються — див.
[docs/PRIVATE.md](docs/PRIVATE.md). Без них локальна розробка працює:
сторінки просто рендеряться системним шрифтом.

## Деплой

Повний ранбук: [docs/self-hosting.md](docs/self-hosting.md). Коротко:

```bash
npm run migrate:prod
npm run deploy       # перевіряє наявність шрифтів, потім wrangler deploy
```

`npm run deploy` читає `wrangler.production.toml`, який лежить лише
локально. Відстежуваний `wrangler.toml` — шаблон.

## Що вміє

- **Сторінки бронювання**, зібрані й віддані з edge
- **Google Calendar та Microsoft 365** через власний OAuth-застосунок
- **Типи подій**: буфери, мінімальний час до зустрічі, горизонт, ліміт на
  день, власні питання
- **Команди** — почергово та разом
- **Листи з `.ics`**, посилання на перенесення й скасування, нагадування
  за 24 год і 1 год
- **REST API**, вебхуки з HMAC-підписом, embed-віджет
- **Вбудований MCP-сервер** — календар як інструмент для AI-агента

## Як це працює

Три рішення визначають усе інше.

**Подвійне бронювання неможливе на рівні сховища, а не за домовленістю.**
Кожне бронювання пише по рядку на пʼятихвилинний слот кожного організатора
в таблицю `slot_locks` з первинним ключем `(host_user_id, bucket_start)` —
у тому ж `batch()` D1, що й саме бронювання. Конфліктний слот порушує
обмеження, і весь batch відкочується. Перетин діапазонів не виражається
SQL-обмеженням, а дискретні слоти — так; ця підміна і є суттю дизайну.
Durable Objects серіалізують спроби та перевіряють зовнішні календарі, але
вони — швидкий шлях, а не гарантія: у найгіршому разі гість отримає 409.

**Усередині весь час у UTC; настінний час існує лише на межах.** Перехід на
літній час обробляється явними правилами: час, що потрапив у «провал»
весняного переводу, зсувається вперед, неоднозначний час осіннього —
береться перше входження, і обидва правила діють однаково для початку й
кінця вікна. Тестова матриця покриває Київ, Нью-Йорк, Лорд-Гав (зсув на
30 хвилин), Чатем (+12:45), Колкату та південну півкулю.

**Рушій отримує все через порти.** Сховище, календарі, пошта, крипто, кеш,
годинник і черга приходять інтерфейсами — саме тому доменний шар не має
жодного імпорту Cloudflare і ганяється під звичайним Node.

## Розробка

```bash
npm test              # 500 тестів
npm run test:core     # лише домен, без Workers-рантайму, ~150 мс
npm run typecheck
```

Адаптери, Durable Objects і HTTP тестуються проти справжнього рантайму
Workers через Miniflare.

## Оновлення з апстріму

```bash
git fetch upstream && git merge upstream/main
npm test && npm run typecheck
```

Конфлікти зосереджені у ~8 перекладених файлах. Перекладай за
[docs/GLOSSARY-UA.md](docs/GLOSSARY-UA.md), щоб формулювання не розʼїжджалися.
